# 01 · 体系结构与性能模型

> **本模块回答**：硬件的能力边界在哪？为什么有些优化能提升 10 倍，有些怎么调都没用？

这是整个清单最重要的模块，也是最容易被跳过的一个。跳过它，后面所有论文都只能靠"名词记忆"。
本模块只需要建立**一个思维习惯**：看到任何一个算子或系统设计，先问——

> **这个操作，是算力受限（compute-bound）还是带宽受限（memory-bound）？**

这个问题的答案，决定了后面所有优化手段的选择。答案的依据就是 Roofline 模型。

如果你完全没有体系结构背景，先补下面这些**再读论文**（不用读完教材，只读指定章节）：

- **CSAPP 第 5 章（优化程序性能）、第 6 章（存储器层次结构）**：理解 cache、局部性、为什么"访存比计算贵"。
  <https://csapp.cs.cmu.edu/>
- **知道这几个指标的含义**：FLOPS（每秒浮点运算次数）、HBM 带宽（GB/s）、SRAM/寄存器容量、L2 cache 大小。

## 论文清单

### 1. Roofline: An Insightful Visual Performance Model for Multicore Architectures

- [ ] **P0** ⭐ · [Roofline: An Insightful Visual Performance Model for Multicore Architectures](https://people.eecs.berkeley.edu/~kubitron/cs252/handouts/papers/RooflineVyNoYellow.pdf) · CACM 2009
  - **主旨**：用一个二维图（横轴 = 计算强度，即每字节访存做多少次浮点运算；纵轴 = 性能）把"硬件的算力上限"和"带宽上限"画在一起，一眼看出一个程序卡在哪一侧。
  - **为什么读 / 读到什么程度**：**精读**。这是全清单的度量衡。你要能画出自己 GPU 的那张图，算出拐点（ridge point）的计算强度，并回答："FP16 下拐点是多少？"（例如 A100 FP16 约 312 TFLOPS / 1555 GB/s ≈ 200 FLOP/Byte）。
  - **前置知识**：上面的 CSAPP 章节。
  - **建议用时**：3 小时（含自己算一遍）。
  - **读完要能回答**：为什么大语言模型的 decode 阶段永远是带宽受限的？（因为每生成一个 token 都要把几百 GB 的权重读一遍，而只做 2 次运算。）

> **为什么这篇最重要**：AI Infra 里 90% 的性能优化，本质上都是在对抗"带宽受限"。FlashAttention、量化、MoE、KV Cache 管理、投机解码——全部是同一个故事的不同章节。先有 roofline 视角，后面每篇论文你都会自动问出正确的问题。

### 2. In-Datacenter Performance Analysis of a Tensor Processing Unit

- [ ] **P0** ⭐ · [In-Datacenter Performance Analysis of a Tensor Processing Unit](https://arxiv.org/abs/1704.04760) · ISCA 2017
  - **主旨**：Google 第一代 TPU 的实测分析论文。核心结论之一是 TPU 的性能经常被**访存带宽和主机通信**卡住，而不是 MXU 的算力。
  - **为什么读 / 读到什么程度**：**精读**。这是"为什么需要专用加速器"以及"为什么 AI 芯片的设计难点不在算力"这两个问题的原始答案。重点读：脉动阵列（systolic array）的工作方式、为什么它不缓存大模型、以及论文中那些"利用率远低于峰值"的解释。
  - **前置知识**：第 1 篇。
  - **建议用时**：3 小时。
  - **中文导读**：这篇的中文解读较多，可搜「TPU ISCA 2017 精读」。

### 3. A New Golden Age for Computer Architecture

- [ ] **P0** · [A New Golden Age for Computer Architecture](https://arxiv.org/abs/1801.00636) · CACM 2019
  - **主旨**：Hennessy 与 Patterson 的图灵奖演讲文章，讲清"摩尔定律与 Dennard 缩放结束后，为什么专用领域架构（DSA）是唯一出路"。
  - **为什么读 / 读到什么程度**：**泛读**。读摘要 + 前三节 + 关于 DSA 和领域专用语言的判断即可。它给你的是"为什么 AI Infra 这个行业存在"的宏观视角，用来串起整个模块。
  - **前置知识**：无。
  - **建议用时**：1.5 小时。

### 4. Efficient Processing of Deep Neural Networks: A Tutorial and Survey

- [ ] **P1** · [Efficient Processing of Deep Neural Networks: A Tutorial and Survey](https://arxiv.org/abs/1703.09039) · Proceedings of the IEEE 2017
  - **主旨**：把 DNN 加速器领域的所有术语（数据流、权重复用、行固定、输出固定、PE 阵列）整理成一套统一语言。
  - **为什么读 / 读到什么程度**：**泛读**。它是当你后来读到"spatial architecture / weight stationary"这类词时的词典。重点读数据流分类那一节。
  - **前置知识**：第 1、2 篇。
  - **建议用时**：2 小时。

### 5. TPU v4: An Optically Reconfigurable Supercomputer for Machine Learning

- [ ] **P1** · [TPU v4: An Optically Reconfigurable Supercomputer for Machine Learning with Hardware Support for Embeddings](https://arxiv.org/abs/2304.01433) · ISCA 2023
  - **主旨**：从单芯片走到**集群**：用光交换（OCS）动态重组互联拓扑，以及为什么"支撑 embedding"成了训练集群的关键需求。
  - **为什么读 / 读到什么程度**：**泛读**。读系统架构图和 OCS 那部分。这是你理解第 04 模块"通信为什么是训练的主要瓶颈"的硬件背景。
  - **前置知识**：第 2 篇。
  - **建议用时**：1.5 小时。

### 6. A Survey of Quantization Methods for Efficient Neural Network Inference

- [ ] **P1** · [A Survey of Quantization Methods for Efficient Neural Network Inference](https://arxiv.org/abs/2103.13630) · 2021
  - **主旨**：量化的术语与分类体系：对称/非对称、per-tensor/per-channel、PTQ 与 QAT、异常值问题。
  - **为什么读 / 读到什么程度**：**泛读**。读到你能区分"训练后量化"和"量化感知训练"，并知道为什么 LLM 的异常值（outlier）让 INT8 特别难做。
  - **前置知识**：第 1 篇（量化的收益本质上是降低带宽需求）。
  - **建议用时**：2 小时。
  - **后续**：第 05 模块的 GPTQ / AWQ / SmoothQuant 是这篇综述在 LLM 上的具体落地。

### 7. 补充选读（P2）

- [ ] **P2** · [You Only Cache Once: Decoder-Decoder Architectures for Language Models (YOCO)](https://arxiv.org/abs/2405.05254) · 2024 —— 一个"用架构改动直接消掉 KV Cache 带宽瓶颈"的例子，读完 05 模块再回来看会很有感觉。
- [ ] **P2** · 任意一篇 DNN 加速器体系结构综述（搜 "DNN accelerator survey"）—— 只在你想往硬件方向走时读。

## 动手验证（本周必做）

1. **算一次 roofline 拐点**：查你手边 GPU 的 FP16 算力与显存带宽，算出 ridge point 的计算强度。
2. **做一次判断**：对下面四个操作，分别判断它是算力受限还是带宽受限，并说明理由：
   - LLM 训练的 forward（大 batch、长序列）
   - LLM 推理的 prefill 阶段
   - LLM 推理的 decode 阶段（batch = 1）
   - LLM 推理的 decode 阶段（batch = 256）
3. **验证一个数字**：查 Llama-3-8B 的参数量，算出 FP16 下把它完整读一遍需要多少字节；用你 GPU 的带宽除以它，得到理论上的单 token 生成延迟下界。你会发现实测能接近这个数字——这就是"decode 是带宽受限"的直接证据。

> 这一周的练习比读论文更重要。做完它，第 05 模块的每一篇论文你都会读得飞快。

## 演进链（谁替代了谁）

```
纯通用 CPU  →  TPU v1（脉动阵列，2017）
            →  TPU v2/v3/v4（加入互联与光交换，走向集群，2018–2023）
            →  H100/B200 等 GPU 加入专用单元（Transformer Engine、FP8）
            →  行业共识：算力不是瓶颈，"喂饱算力"才是 —— 这条路直接通向 03 模块的 FlashAttention
```
