# 08 · 前沿专题选读

> **本模块回答**：带着前七个模块的地基，怎么判断新论文的价值？

这个模块**不给完整清单**，而是给**六条演进链**。每条链的前半部分你在前 7 个模块已经读过，后半部分是"今天正在发生的事"。

## 专题 1：长上下文（Long Context）

**你已经读的**：FlashAttention（03）、Ring Attention（04）

**这条链在解决什么**：序列长度增加时，attention 的 $O(N^2)$ 计算和 KV Cache 的线性增长同时成为瓶颈。三个方向：更省访存的 kernel（FlashAttention 线）、跨卡切分序列（Ring Attention 线）、直接改架构减少 KV Cache。

- [ ] **P1** · [Striped Attention: Faster Ring Attention for Causal Transformers](https://arxiv.org/abs/2311.09431) · 2023
  - Ring Attention 在因果注意力下各卡负载严重不均（前面的卡算得多）。Striped Attention 把序列按"条纹"而非连续块分配，使各卡负载均衡。
- [ ] **P2** · [You Only Cache Once: Decoder-Decoder Architectures for Language Models (YOCO)](https://arxiv.org/abs/2405.05254) · 2024
  - 用"全局 KV 只算一次 + 逐层复用"的架构直接消除逐层 KV Cache。
- [ ] **P2** · [LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens](https://arxiv.org/abs/2402.13753) · 2024
  - 从位置编码角度扩展上下文——属于"算法侧解决系统问题"的例子。

> **链末问题**：把上下文从 8K 提到 1M，成本增长在哪几个维度？哪些是系统能解决的，哪些必须靠模型架构解决？

## 专题 2：MoE 系统（Mixture-of-Experts）

**你已经读的**：GShard / Switch Transformers（04）、MegaBlocks（04）、DeepSeekMoE（04）

**这条链在解决什么**：MoE 让参数量与计算量解耦，但把压力全转移到了**通信（all-to-all）与负载均衡**上。今天所有大模型训练报告里，MoE 的系统部分是重头戏。

- [ ] **P1** · [DeepSeek-V3 Technical Report](https://arxiv.org/abs/2412.19437) · 2024
  - 重点读：**无辅助损失的负载均衡策略**、节点受限路由（node-limited routing）、以及 FP8 训练的实现细节。这是目前公开材料里 MoE 训练工程细节最完整的一份。
- [ ] **P2** · [DeepSeekMoE: Towards Ultimate Expert Specialization](https://arxiv.org/abs/2401.06066) · 2024
  - 更细粒度的专家拆分（共享专家 + 路由专家），是 DeepSeek-V3 的架构基础。

> **链末问题**：MoE 的 all-to-all 通信量由什么决定？为什么"专家并行度"不能无限放大？

## 专题 3：后训练与 RLHF Infra

**这是 2024 年以来最热的新方向**，因为 RLHF/RLVR 把"训练"变成了"推理 + 训练交替"的复杂流水线。

- [ ] **P1** · [HybridFlow: A Flexible and Efficient RLHF Framework](https://arxiv.org/abs/2409.19256) · 2024
  - **主旨**：RLHF 的四个模型（actor / critic / reward / reference）需要在训练与推理两种模式之间反复切换，且各有不同的并行策略需求。HybridFlow（即开源项目 verl 的论文）用"单控制器 + 混合编程模型"把这种复杂编排变得可表达、可调度。
  - **为什么读 / 读到什么程度**：**泛读**。重点理解"为什么 RLHF 的系统问题和传统训练不一样"（资源在生成与训练之间来回切换、利用率低）。
  - **前置知识**：04 模块 + 05 模块（它同时用到两边的技术）。
  - **建议用时**：2 小时。

> **链末问题**：RLHF 训练为什么 GPU 利用率通常远低于预训练？有哪几种思路提升它？（提示：colocate、异步生成、分离部署——每个词你都在 05 模块见过。）

## 专题 4：低精度训练

**你已经读的**：LLM.int8() / GPTQ / SmoothQuant / AWQ（05，都是推理侧量化）、量化综述（01）

**这条链在解决什么**：把量化的收益从推理搬到训练，收益更大（显存、通信、算力同时下降），难度也更大（梯度与优化器状态对精度敏感）。

- [ ] **P1** · [Scaling FP8 training to trillion-token LLMs](https://arxiv.org/abs/2409.12517) · 2024
  - 系统性地解决 FP8 训练中的量化误差累积问题（尤其是对 attention 分数和梯度的影响）。
- [ ] **P2** · [DeepSeek-V3 Technical Report](https://arxiv.org/abs/2412.19437) · 2024（同上）第 3 节
  - 看工业界如何做到大规模 FP8 训练并保证不崩。

> **链末问题**：为什么训练侧的量化比推理侧难？哪些张量可以放心用低精度，哪些不行，为什么？

## 专题 5：扩散模型与多模态的并行推理

**这条链的作用**：证明你在 03、04 模块学到的东西**不限于 Transformer**。同一个"带宽受限 → 分块并行"的思路，在扩散模型上会得出完全不同的系统设计。

- [ ] **P2** · [DistriFusion: Distributed Parallel Inference for High-Resolution Diffusion Models](https://arxiv.org/abs/2402.19481) · CVPR 2024
  - **主旨**：扩散模型的去噪步骤之间有强时序依赖，不能简单按 batch 并行。DistriFusion 把单张图切块分到多卡，并**复用上一步的特征**来补偿块之间的边界不一致问题。
  - **为什么读 / 读到什么程度**：**泛读**。读第 3 节的方法。
  - **建议用时**：1.5 小时。

> **链末问题**：为什么扩散模型的并行比 LLM 推理更难？"用历史结果填补依赖"这一招在别的地方见过吗？（提示：流水线并行的权重陈旧性。）

## 专题 6：KV Cache 为中心的架构

**你已经读的**：PagedAttention / vLLM（05）、SGLang / RadixAttention（05）

**这条链在解决什么**：把 KV Cache 从"每个实例内部的实现细节"提升为"整个集群共享的一等资源"。

- [ ] **P1** · [Mooncake: A KVCache-centric Disaggregated Architecture for LLM Serving](https://arxiv.org/abs/2407.00079) · FAST 2025
  - **主旨**：把集群里闲置的 GPU、CPU 内存甚至 SSD 组织成分层 KV Cache 池，跨实例复用；prefill 与 decode 集群分离，由调度器决定"从哪个缓存节点取 KV 最划算"。
  - **为什么读 / 读到什么程度**：**泛读**。重点读架构图与调度策略。它是"PD 分离 + 前缀复用"两条线的汇合点。
  - **前置知识**：05 模块全部。
  - **建议用时**：2 小时。

> **链末问题**：如果 KV Cache 成为集群级共享资源，会引入哪些新问题？（一致性、淘汰策略、网络带宽、与 PagedAttention 的交互。）

## 如何自己跟踪前沿（比读完任何清单都重要）

1. **盯会议**：MLSys（系统 + ML 最集中）、OSDI/SOSP（系统经典）、NSDI（网络与集群）、ASPLOS/ISCA（体系结构）、ICML/NeurIPS（算法与系统的交叉）。
2. **盯开源项目的 release note**：vLLM、SGLang、DeepSpeed、Megatron-LM、TensorRT-LLM 的更新日志里，80% 的新技术都能找到对应论文。
3. **盯技术报告**：各大模型的技术报告（DeepSeek-V3、Llama 3、Qwen）中都有大段 Infra 章节，是"工业界真实做法"的第一手材料。
4. **判断一篇新论文值不值得读**（用前七个模块的框架）：
   - 它属于哪一层（01–07 的哪个模块）？
   - 它优化的是哪个指标（吞吐 / 延迟 / 显存 / 通信 / 恢复时间）？
   - 它把什么换成了什么？代价是什么？
   - 它的假设在你的场景里成立吗？

> 能快速回答这四个问题，你就不再需要别人给你推荐论文了。
